# 闭环搜索里谁决定什么：规则 / 科学模型 / 人 / agent

> 适用范围：`loop` 分支的高 κ 闭环搜索（run `loop-v1`，2026-11-11 起）。
> 这份文档回答三个问题：候选池是谁生成的、每一轮选哪些结构是谁定的、agent 具体做了什么。
> 原则（DESIGN §11.4）：哪些是 agent 决定的、哪些是人决定的、哪些是固定脚本，要分开写清楚，不夸大 agent 的作用。

---

## 1. 一句话

**选什么结构由科学模型决定，怎么算由带出处的协议决定，算多少由人批准。** agent（Claude Code）负责把流程跑通：诊断失败、在参数允许的范围内提出改动并写明理由、估算成本、安排 GPU、监控和取回结果、起草下一轮。它**不生成结构，也不凭直觉挑结构**。

---

## 2. 流程总览与每一步的决定者

```
候选池 (804)  ──relax──▶  L0 (FC2 描述符, 稳定性)  ──▶  L0 稳定 (314)
                                                          │
                     ┌────────────────────────────────────┘
                     ▼
          分层抽样 L1 (118, 一次性)  ──▶  L1 标签 (κ_RTA, 300 K)
                     │                          │
                     ▼                          ▼
          GP 代理模型 (17 个 L0 特征 → log10 κ_L1)  ◀── 每轮重新拟合
                     │
                     ▼
          UCB 排序 + 硬约束  ──▶  下一批 10 个  ──(人批准)──▶  L1  ──▶ 循环
```

| 步骤 | 做什么 | 由什么决定 | agent 的角色 |
|---|---|---|---|
| 候选池 | 原型装饰 + 有序枚举 + 同族替换 | **确定性脚本** `scripts/build_pool.py`、`scripts/trim_pool.py`（规则由用户 11-11 批准） | 执行脚本、导入集合；不生成结构 |
| 弛豫 | DPA-4.1 弛豫 | **协议默认值**（κ_SRME 官方实现：fmax 1e-4 等） | 失败后诊断并提出重试方案（见 §5） |
| L0 | FC2 描述符、虚频判断、Slack 估计 | **协议** + 稳定性规则（没有虚频才算稳定） | 处理 OOM 和失败，安排 GPU |
| L1 初始样本 | 118 个结构 | **确定性分层抽样** `scripts/sample_l1.py`（化学体系 × Slack 三分位） | 提出预算；**人批准** |
| 每轮选结构 | 下一批 10 个 | **GP + UCB**（`scripts/loop_round.py`）+ 硬约束 | 选排除集 / 在算集、跑 dry-run、报告成本；**人批准提交** |
| L1 计算 | phono3py Wigner-RTA，300 K | **κ_SRME 协议**（0.03 Å 位移、phono3py 3.30.0 等） | 超胞宽度、GPU 类型、时限、chunk 大小：提出方案，人批准 |
| 命中判定 | κ_L1 ≥ 阈值 | **规则**：L1 样本 κ 的 90 % 分位（当前 537.7 W/mK） | 不参与 |

## 3. 候选池：不是 agent 生成的

候选池是**确定性枚举**出来的，没有随机结构，也没有生成模型。agent 在运行时不会「想出」新结构。

### 3.1 生成规则（`scripts/build_pool.py`）

| 来源 | 数量 | 规则 |
|---|---|---|
| `enum` | 447 | 闪锌矿 / 纤锌矿 / 岩盐超胞（≤ 8 原子）上的有序占位，按固定氧化态电荷平衡（四面体网络的 8 电子规则） |
| `bcn` | 570 | 闪锌矿 / 纤锌矿超胞的每个位点放 B/C/N，要求 n(B) = n(N)（类金刚石网络） |
| `subst` | 135 | 库中原型（项目已有的 L0 稳定结构 + MP 结构）做同族元素替换，体积按共价半径缩放 |
| `known` | 57 | MP 结构（E_hull ≤ 0.3 eV/atom），作为锚点 |

**统一的硬限制**：
- 16 个化学体系（B–N、B–C–N、As–B–P、Be–O、Al–B–N 等轻元素、强共价体系）；
- 原胞 ≤ 8 原子；每种元素 ≤ 4 种；每个子晶格 ≤ 2 种元素；最短原子间距 ≥ 1.2 Å。

**去重**：先用母超胞的空间群约化装饰方式，再用近邻签名和 StructureMatcher 去重，得到 1209 个。

**为什么这样设计**：
- 高 κ 的经验规律（Slack）：轻元素、强共价键、结构简单、原胞原子少。
- 小原胞同时决定了 L1 的成本，因为 FC3 超胞大小随原胞原子数增长。

### 3.2 裁剪（`scripts/trim_pool.py`）

B–C–N 三元占了 605 个，会让回放曲线被一个体系主导，所以裁到 200 个：
- 按化学式轮流取；
- 同一化学式内，空间群对称性高的优先，原胞小的优先；
- R3m-BC₂N 阳性对照永远保留。

最终池子是 **804 个**结构（集合 `loop.pool.v1.bcn200`）。

### 3.3 隐藏目标与防泄漏

- 池子里有 157 个化学式与 κ_SRME 测试集重合的结构。它们只作为「重新发现」的检验目标。
- κ_SRME 的 103 个测试条目（70 个化学式），包括其所有多形体，都不进入训练、回放或调参数据。

### 3.4 之后的扩池（计划，`scripts/grow_pool.py`）

扩池也是确定性的：
- 取一轮里排名靠前的结构作父代。排名有 L1 标签就用标签，没有就用 GP 均值。
- 做同一套同族替换，然后去重。

新结构要和其他池子成员一样，经过 relax → L0 → 代理模型才可能被选中。agent 的作用只是在合适时机提议运行，并报告新增结构数。

## 4. 每一轮选结构：是 GP 选的

### 4.1 代理模型（`src/mga/loop/surrogate.py`）

- **模型**：高斯过程。核函数是 Matern-5/2 ARD 加白噪声，特征先标准化。
- **输入**：17 个 L0 特征（`src/mga/loop/data.py: FEATURES`）。包括：
  - Slack 估计、声学 Debye 温度、平均原子质量、声学 / 总群速度、a-o gap 比、声学 Grüneisen、加权相空间等；
  - 其中跨数量级的量取 log。
- **输出**：log10 κ_L1 的均值 μ 和不确定度 σ。
- **训练集**：当前全部 L1 标签。r1 用了 84 个，r2 用了 98 个。每轮都从头重新拟合。

### 4.2 采集策略

**当前策略**：`slack_ucb`。真实轮次里它与 `ucb` 完全相同，按 **μ + β·σ（β = 1）从高到低**排序。

**为什么用它**：这是回放实验比出来的，不是 agent 的偏好。
- 用已有标签做模拟，5 种策略 × 20 个随机种子。
- GP 策略找到命中的速度约为随机的 2 倍。
- `slack_ucb` 用 Slack 冷启动，开局最快。

### 4.3 排序之后的硬约束（`scripts/loop_round.py`）

按 UCB 顺序往下取，跳过不满足以下条件的结构，直到取满 10 个：

1. **不在排除集里**：已经算过或正在算 L1 的结构（`--exclude-set`）。
   - 失败的 L1 没有标签，不排除的话会被反复选中。
2. **每个化学式最多 2 个**（`--max-per-formula 2`）。
   - 同一化学式的多形体描述符几乎相同，没有这个上限的话，UCB 会把一批全花在一个点上。
   - 仍在计算中的结构也计入这个上限（`--pending-set`）。
3. **FC2 超胞原子数上限**（可选，`--max-fc2-atoms`）。
   - 例：r2 设了 360，保证全部能在 L40S 上算，不和 A100 上的长任务抢卡。

### 4.4 「decided_by: human」的含义

两条 `loop_round` 记录（r1、r2）都是 `decided_by: human`。这表示**本轮的参数是人确认过的**，具体是策略、β、批量、排除集、FC2 上限这些。**哪 10 个结构入选**仍由 GP + UCB + 上述约束机械地算出。

人和 agent 都没有手工增删入选结构。如果以后需要手工干预，必须单独记录。

## 5. 三类决定的分界

### 5.1 由规则、科学模型和协议决定（agent 不能改）

| 内容 | 值 / 规则 | 来源 |
|---|---|---|
| κ 计算协议 | Wigner-RTA，300 K，0.03 Å 位移，`is_isotope`，phono3py 3.30.0，无 NAC | κ_SRME 官方实现（Matbench Discovery） |
| 弛豫协议 | 单步对称性弛豫，fmax = 1e-4 | 同上 |
| 超胞长度规则 | FC3 ≥ 8 Å；FC2 默认 14 Å；q 网格长度 40 Å | phononDB 启发式（标为启发式，FC2 宽度做过收敛检查） |
| 稳定性判断 | L0 没有虚频才算稳定 | 规则 |
| 候选池 | §3 的枚举规则 | 确定性脚本 |
| L1 初始样本 | 化学体系 × Slack 三分位，配额 ∝ √n | 确定性脚本；设计上不偏向任何策略 |
| 每轮选择 | GP（Matern-5/2 ARD）+ UCB（β = 1）+ 化学式上限 | 回放实验选出的策略 |
| 命中阈值 | L1 样本 κ 的 90 % 分位 | 规则 |
| 防泄漏 | κ_SRME 测试化学式不进训练 | 规则 |
| 成本模型 | GPU·h = 3.55e-8 × FC3 位移数 × FC3 原子数^1.757 | 对 98 个 L1 实测耗时的拟合（数据决定，不是 agent 估计） |

这些参数都写在 `src/mga/specs.py` 的参数 schema 里。每个默认值都带 `source` 字段注明出处，并进入结果缓存的哈希。

### 5.2 由人决定（审批闸门）

**两类硬性审批**：
- 大规模计算（任何一批 L1，以及大批量 L0）提交前，agent 必须先报告结构数和 GPU·h，等人同意。
- VASP 和微调走 `mga approvals` CLI。这个 CLI 只能在交互终端里批准，没有对应的 MCP 工具；`MGA_ACTOR=agent` 时直接拒绝运行。这是防止误提交的护栏，不是安全边界。

**本次运行中人做的决定（都在记录里，`decided_by: human`）**：

| 日期 | 决定 |
|---|---|
| 11-11 | 批准候选池设计；B–C–N 裁到 200；L40S OOM 的结构改用 A100 重算 |
| 11-12 | L0 的 FC2 宽度从 14 Å 降到 10 Å（L0 只是筛选，选项 C） |
| 11-13 | 批准 118 个结构的 L1 预算；L1 的 FC2 宽度做收敛检查 |
| 11-14 | r1 用 FC2 12 Å，OOM 的改 10 Å 重算；chunk_size 改为 1（一个结构一个作业） |
| 11-15 | r1 两个大结构取消后按 3 天时限重提；r2 只用 L40S，在算结构计入化学式上限 |

### 5.3 agent 可以根据结果灵活决定（不超出 schema，并写明理由）

| 类别 | 具体内容 | 本次运行的例子 |
|---|---|---|
| **失败诊断** | 读日志，判断 OOM / 超时 / 虚频 / 对称性破缺 / runner 卡死 | 79 个 Pm 结构弛豫报 torch size error、258 个达到 max_steps：诊断后换成对称化的常规胞重试（`decided_by: agent`） |
| **数据清洗** | 去重、剔除不物理的结构、合并集合 | 删除 a = 1.77 Å 的简单立方 C；三次 L0 提交合并为一个集合 |
| **schema 内的参数覆盖** | 每个覆盖必须通过类型和范围检查，并带 `override_reason` | 常规胞 L0 OOM 后改回原胞重算 |
| **资源安排** | 按超胞大小分配 L40S / A100，设作业时限和 chunk 大小 | FC2 ≤ 360 原子 → L40S，≤ 672 → A100，更大的降到 10 Å |
| **成本估计** | 用实测耗时拟合成本模型，在提交前算出 GPU·h 和 10–90 % 区间 | 发现线性模型对 384 原子的胞低估约 3 倍，改成幂律 |
| **下一轮草稿** | 选 `--exclude-set` / `--pending-set` / `--max-fc2-atoms`，跑 dry-run，把结构、成本、GPU 分布报告给人 | r2 是否等 r1 大结构：给出选项和推荐，人决定 |
| **监控与取回** | 后台监控作业，完成后取回结果、重新拟合 GP | 23 条 `fetch_results` 记录 |
| **基础设施修复** | 运行器、SSH、配置问题 | WSL 休眠后 jf runner 卡死：加 `connect_timeout` 和 SSH keepalive |
| **建议（不执行）** | 是否重算、是否降超胞、是否扩池 | 建议不重算超时的 BPC2（μ ≈ 50 W/mK，重算约 19 A100·h），等人决定 |

**agent 不能做的事**：
- 改协议默认值；
- 手工挑选或增删一轮的入选结构；
- 绕过 GP 选结构；
- 未经批准提交大规模计算；
- 批准 VASP 或微调；
- 在登录节点上计算。

## 6. 决定记在哪里

每一步都写一条记录：`runs/loop-v1/records/*.json`，由 `src/mga/records.py` 写入。

| 字段 | 含义 |
|---|---|
| `actor` | 谁执行了这一步（几乎都是 agent，因为工具由 agent 调用） |
| `decided_by` | 谁决定了这一步的输入：`human` / `agent` / 空（纯取数和计算，如 `fetch_results`、`compute_ehull`） |
| `rationale` | 理由，人决定的会写明「User approved 11-xx …」 |
| `params` 的出处 | 每个参数标明是默认值（带 `source`）还是覆盖（带 `override_reason`） |

截至 11-15，66 条记录的分布：

| decided_by | 条数 | 主要类型 |
|---|---|---|
| human | 25 | 全部 L1 提交（8）、两轮 `loop_round`、`sample_l1`、`trim_pool`、导入候选池、FC2 宽度变更 |
| agent | 14 | 弛豫失败重试、去重、对称化、首次 L0 提交、合并集合、剔除不物理结构 |
| 空 | 27 | `fetch_results`、`compute_ehull`、`kappa_convergence` |

**规律**：凡是花大量 GPU、或改变科学结论口径的决定，都是 `human`。agent 自主决定的都是**修复性**和**整理性**的步骤。

## 7. 评估这个分工时要如实说的几点

- 「闭环」里学习的部分是 **GP 代理模型**，不是 LLM。LLM agent 的价值在于工程层面：把一个多步骤、跨集群、经常失败的计算流程持续跑下去，并留下可审查的记录。它不在于科学判断。
- 回放实验比较的是**选样策略**（random / slack / greedy / ucb / slack_ucb），不比较「agent vs 人」。
- 候选池的规则（16 个体系、≤ 8 原子）带有先验偏向。池子外的高 κ 结构，这个流程原则上找不到。
- L1 是 MLIP（DPA-4.1）+ RTA 的结果。RTA 会低估高 κ 材料；L2（LBTE）和更高级别只给排名靠前的结构做。
